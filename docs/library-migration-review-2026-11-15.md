## 原审查结论

发现 7 项问题：2 项 P1、5 项 P2。最优先的是迁移期间缺乏持续互斥，以及文件与两份配置之间缺乏可恢复提交。

| 编号 | 级别 | 问题 | 证据 |
| --- | --- | --- | --- |
| LM1 | P1 | 迁移中仍可开始游戏及文件操作，源目录的新写入可能在清理时丢失。 | 实际服务与 AppState 隔离复现 |
| LM2 | P1 | 新目录、store.json、library-config.json 分别提交，中断或回滚失败会留下不一致状态。 | 命令、仓库与启动恢复调用链审查；未注入真实应用故障 |
| LM3 | P2 | 漏迁 covers，切换根目录后已有封面无法读取。 | 实际服务隔离复现、封面读取调用链 |
| LM4 | P2 | 非迁移范围的 verbatim UNC 路径被改成相对路径。 | 实际路径改写隔离复现 |
| LM5 | P2 | 路径重叠检查仅比较字符串，带 .. 的重叠目标可以通过。 | 实际校验函数隔离复现；未执行危险复制 |
| LM6 | P2 | 旧库清理失败仍结束为成功，前端明确声称已清理。 | 文件占用隔离复现、终态覆盖调用链 |
| LM7 | P2 | 迁移任务跟踪遇一次 IPC 失败便中断，重进页面不接续，也不使游戏库缓存失效。 | 实际 Vue setup 隔离复现、App 任务观察器审查 |

## LM1：迁移期间没有持续的全局互斥（P1）

位置：

- `src-tauri/src/commands/library_commands.rs:45`：迁移开始前只检查一次运行游戏与 save_operations，随后释放检查用的锁。
- `src-tauri/src/app_state.rs:183`、`:202`：整游戏及云端操作认领不检查 library_migration；启动游戏使用的 has_exclusive_operation 也不检查该标志。
- `src-tauri/src/services/task_service.rs:24`：任务创建只拦截账号恢复独占，不拦截游戏库迁移。
- `src-tauri/src/services/library_service.rs:87`、`:118`：复制校验只比较总大小与文件数，之后删除源库三个大目录。

触发：迁移开始后启动游戏，或开始新增游戏、本体打包、存档写入等操作。这些流程仍可能持有旧库路径。迁移入口也没有完整检查已在运行的后台任务和学习会话。

隔离复现：源文件为 `OLD`；实际 migrate 的逐文件进度回调中将源文件改成同长度的 `NEW`。大小与数量校验成功，新目录仍为 `OLD`；实际 cleanup_source 随后删除包含 `NEW` 的旧目录。另一个测试直接把实际 AppState 的迁移标志设为 true，整游戏与云端操作仍都能认领成功。

影响：刚写入的存档或新增游戏文件可能被收尾清理删除；已经启动的任务也可能继续向旧库写入。此处问题是缺乏操作隔离，不能靠增加全库 SHA-256 扫描根治。

建议：复用现有操作集合做迁移全局独占；在同一协调机制下检查并阻止冲突任务、运行游戏与学习。覆盖读取旧根路径到实际文件操作的完整期间，成功、普通失败和异常退出均正确释放或恢复状态。

## LM2：提交与回滚无法保证一致性（P1）

位置：`src-tauri/src/commands/library_commands.rs:169–211`；`src-tauri/src/lib.rs:72–84`。

实际顺序：

1. migrate 把整库复制并提交到目标目录。
2. 改写当前 store 并持久化 store.json。
3. 保存 library-config.json 中的新根目录。
4. 更新内存根目录并清理旧库。

这几步之间没有迁移日志或启动恢复。若在步骤 2 与 3 之间退出，重启会用旧配置根目录加载新路径的 store。单个 JSON 的原子替换和残留恢复不保证这两份文件之间的一致性。

配置保存失败时，代码忽略反向路径改写与 store 持久化的回滚结果，随后仍删除目标目录。若回滚落盘失败，磁盘 store 仍可能指向刚删除的新目录。源文件通常仍在旧库，这不等同于所有游戏内容已永久丢失，但应用引用已损坏，需要修复才能正常使用。

另一分支：目标目录提交成功后，store 持久化若直接报错，函数通过 `?` 返回，不清理已提交的新目录。会遗留一份无有效配置指向的整库副本；相同目标重试又会因目录非空被拒绝。

建议：采用简洁的迁移提交记录，记录源、目标与已完成阶段，启动时能够完成或回退。回滚失败必须报告并保留可恢复的目录，不能无条件删除目标。尚未提交引用时的复制残留应明确清理或登记，避免静默占用整库空间。本项来自实际调用顺序审查，未对真实应用制造断电或磁盘故障。

## LM3：封面遗漏（P2）

位置：`src-tauri/src/services/library_service.rs:25–30`、`:78`、`:118`；`src-tauri/src/commands/game_commands.rs:223–224`。

统计、复制和清理都只枚举 games、body-packages、saves。封面实际位于库根目录的 covers 下，store 保存相对路径，读取时与当前库根组合。

隔离复现：旧库有 `covers/game-a/cover-a/display.jpg`，迁移成功后目标不存在该文件，旧库仍保留原文件。实际切换根目录后封面读取会指向缺失的新路径。

建议：把 covers 纳入同一份库内受管目录定义，用于统计、复制、验证与确认后的清理；不改动封面相对路径的语义。

## LM4：迁移改坏外部 UNC 路径（P2）

位置：`src-tauri/src/services/library_service.rs:203–237`。

rewrite_path 在判断是否属于源目录之前，先去掉 `\\?\UNC\`，却没有补回 UNC 的 `\\`。例如迁移本地 E 盘库时，原本完全不属于该库的自定义存档目录 `\\?\UNC\server\share\Save`，会被改成相对路径 `server\share\Save`。

隔离测试通过实际 rewrite_paths_in_place 复现；未连接网络共享目录。

建议：复用项目现有 verbatim 路径处理；匹配只用规范化表示，不属于迁移范围的路径应保持原义。UNC 前缀去除时必须保留网络绝对路径语义。

## LM5：重叠路径检查可被别名绕过（P2）

位置：`src-tauri/src/services/library_service.rs:34–43`、`:225–249`。

normalized 只处理大小写、分隔符及部分前缀，不消解 `..`，也不识别文件系统别名。隔离测试建立 source/games 与 bridge，目标填写 `bridge/../source/games/nested`。目标父目录 canonicalize 后就是源库的 games，validate_target 却返回成功。

若继续迁移，暂存目录会位于正在复制的 games 子树内，存在复制自身、路径不断增长或空间耗尽的风险。审查没有真的执行此类危险复制，已验证的是重叠校验确实放行。

建议：对已存在的源和目标父目录解析真实路径，对尚不存在的尾部安全拼接；在创建暂存目录前再次确认源、目标、暂存目录互不嵌套。只做字符串前缀比较不足以支持这一安全约束。

## LM6：清理失败被成功状态覆盖（P2）

位置：`src-tauri/src/commands/library_commands.rs:213–225`、`:120–129`；`src/components/PlatformSettings.vue:143–148`。

cleanup_source 失败后仅写错误日志和 98% 的临时进度，函数仍返回 Ok；外层立即将任务覆盖为 100% 成功。前端随后固定显示“原位置的大文件已清理”。

隔离复现：复制成功后，使用 Windows 不共享删除权限的文件句柄占用旧库文件；实际 cleanup_source 返回错误，新旧两份文件均仍存在。命令把错误覆写成成功的部分由调用链确认，没有在真实游戏库制造文件锁。

影响：旧库可能残留完整游戏，继续占用大量空间，用户却收到相反提示。若此前已删除部分目录，还可能留下难以判断的半清理状态。

建议：区分“新库已切换”和“旧库已清理”。清理失败保留可见警告与准确的残留位置，提供安全重试，不能让短暂进度文本充当最终结果。

## LM7：前端迁移状态跟踪不可靠（P2）

位置：`src/components/PlatformSettings.vue:120–156`、`:259–262`；`src/App.vue:371–396`。

两个场景已执行实际 Vue setup 复现：

1. 首次 getTask 返回运行中，定时器下一次读取抛出 IPC 错误。定时回调中的 Promise 没有 catch，发生未处理拒绝，没有后续定时器；libraryTaskId 仍有值，按钮一直处于迁移中，页面也没有显示跟踪失败。
2. 页面已有 set_library_root 运行任务时重新挂载，libraryTaskId 仍为空，不会接续任务。卸载页面时原轮询又会被清除。

另外，App 的任务成功处理涵盖游戏会话、云端安装、账号恢复，没有处理 set_library_root。迁移完成不会主动使游戏库缓存和依赖旧路径的数据失效；当前设置页成功分支也只刷新设置视图。

建议：复用已有共享任务流跟踪迁移，重新进入时接续活跃任务，读取失败可恢复；终态只处理一次，并在切换成功后使游戏库相关缓存失效。无需为迁移再建立一套独立轮询机制。
