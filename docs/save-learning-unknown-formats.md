# 未知格式存档识别

ETW 学习不应依赖逐游戏扩充扩展名白名单。此前 Ntraholic 的目录已被发现，但 `.dontdeletethisdata` 文件在候选筛选时丢失；仅补这一种扩展名不能解决其他未知格式。

## 识别依据

- ETW 仍按目标进程及其生命周期采集，不扩大为全用户目录扫描。
- 常见存档线索保留；未知扩展名和无扩展名文件也可依据同一进程、同一文件对象或路径的完整写入与关闭，或写入后重命名进入候选。
- 只有打开、创建、关闭、未完成的写入，或无法关联的进程、对象、时间，不足以让未知格式进入候选。
- 日志、缓存、临时产物、已知资源文件和大小上限仍按现有规则过滤。原子保存使用采集时配对的写入，即使中间文件名随机或没有扩展名。保护范围取最终仍可读取的目标文件。
- 未知格式即使具有完整写入证据，也仅标记为待确认：完整写入能证明文件发生变化，不能单独证明它是存档。确认界面明确说明依据。
- 只读预览和快照回退没有 ETW 完整写入证据，继续采用保守的存档特征判断。

## 确认后的保护

未知格式候选默认仅保护用户确认的文件。用户可开启自动保护，让同一相对目录内、扩展名和末尾编号前的文件名一致的新档位也进入版本。例如确认 record001.bin 后可以纳入 record002.bin。无扩展名档位适用相同的编号规则。

关闭自动保护、显式排除、噪音和资源过滤仍生效。备份可以收集按编号规则推断出的新档位。恢复旧版本时，这类档位必须已出现在备份历史中，才可以作为多余档位移除。

## 回归范围

使用隔离目录与构造的 ETW 操作验证未知扩展名、无扩展名、原子重命名、缺失或不匹配的关闭事件、噪音和资源过滤、外部目录推断、待确认等级，以及未来档位在备份与恢复两侧的一致性。不修改真实游戏存档。
