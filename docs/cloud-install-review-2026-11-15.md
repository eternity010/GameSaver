# 云端下载并安装审查

日期：2026-11-15

项目：GameSaverNext 1.0.31

范围：商店下载入口、百度下载、ZIP 校验与解压、安装提交、失败恢复、游戏库刷新。

本文件先记录审查时发现的问题，再记录本轮修复结果。下方“修复前发现”中的代码行号和行为对应修复前快照；修复状态、当前行为和验证结果见文末。没有下载、覆盖或删除真实游戏，也没有执行真实百度网盘端到端测试。

## 修复前发现

### 1. [P1] 新安装记录可能丢失云端 gameKey

- 位置：`src-tauri/src/commands/baidu_commands.rs:1679`、`:1690`、`:1983`。
- 新游戏使用 `Game::new_pending(catalog.display_name, ...)`，从显示名称推导 gameKey；后续辅助函数仅在该键为空或路径不安全时才采用远端键。
- 当游戏改过显示名称，或者创建时确认的 gameKey 与名称不同，新环境安装就可能保存错误关联。例如远端键为 `black_market`、名称为 `Black Market v1.23`，本地会保存 `black market v1.23`。
- 商店通过 gameKey 判断是否已安装（同文件 `:333`），云存档也按键定位。结果可能是安装成功后商店仍显示可下载，且找不到原键下的云存档。
- 修复方向：区分“已有本地记录”和“刚构造的新记录”。新记录必须使用已校验的远端 gameKey；不要把新记录的名称推导值当作已有稳定身份。另行明确通过 UID 命中但 gameKey 不一致时的冲突处理。

### 2. [P1] 目录提交与游戏记录提交之间存在无法自动恢复的窗口

- 位置：`src-tauri/src/commands/baidu_commands.rs:1673`、`:1701`、`:1753`；`src-tauri/src/services/game_body_package_service.rs:142`。
- 暂存目录重命名到正式位置后，暂存守卫立即解除，之后还要联网读取封面，最后才保存游戏记录。
- 在此期间强制退出或断电，正式目录已经存在，游戏记录却未提交。启动恢复只清理 `.<uid>.cloud-installing` 暂存目录，不处理已重命名的未登记目录。
- 新游戏因此可能不出现在游戏库，重试又被“游戏受管目录已存在”阻止。现有记录的重装则可能有本体却缺少本次版本记录。
- 修复方向：把非必要网络操作移出提交窗口；使用持久化安装提交记录，让启动时能够完成登记或清理本次未提交目录。普通错误与进程中断都必须有明确恢复路径。

### 3. [P2] 按 gameKey 找到本地游戏后，仍用本地 UID 验证远端 ZIP

- 位置：`src-tauri/src/commands/baidu_commands.rs:1550`、`:1649`；`src-tauri/src/services/game_body_package_service.rs:690`。
- 安装器允许按 gameKey 关联本地记录，但解包时要求 ZIP 内的 `manifest.game_uid` 与本地 UID 完全相等。
- 同一 gameKey 的本地记录 UID 与上传端 UID 不同时，合法本体包会在完整下载后报“本体包不属于当前游戏”。这与使用 gameKey 跨环境关联的模型冲突。
- 同时，入口在 `baidu_commands.rs:446` 预留的是传入的远端 UID，而工作线程可能操作另一个本地 UID。本地更新、删除等按本地 UID 加锁，不能与该安装任务形成正确互斥。
- 修复方向：先解析本地操作身份并以它预留互斥；将云端包来源身份校验与本地记录身份分开，不要简单移除所有来源校验。

### 4. [P2] 云端版本清单读取失败时，安装会静默跳过预期 SHA-256 对比

- 位置：`src-tauri/src/commands/baidu_commands.rs:1535`、`:1569`；`src-tauri/src/services/game_body_package_service.rs:676`。
- 安装器对清单读取结果使用 `.ok().flatten()`，网络错误、解析错误等都会降为没有清单。随后预期 SHA-256 为空，解包器只在存在预期值时做比对。
- 下载虽然计算了实际 SHA-256，但没有与可信预期值比较时，并未完成预期的整包一致性验证。ZIP 结构、CRC 和大小检查仍存在，因此不是完全没有校验。
- 对照：同文件 `download_body_task` 在 `:1121` 会传播清单读取失败，并在清单存在时拒绝未登记的包；商店安装入口没有采用同样约束。
- 修复方向：区分清单确实不存在与清单读取失败；读取失败应明确停止。选中的清单记录还应与远端路径、fsId、包大小、包内版本标识一致，校验后才能提交。

### 5. [P2] 部分损坏的本地目录无法通过商店重新安装修复

- 位置：`src-tauri/src/commands/baidu_commands.rs:1577`、`:1670`。
- 判断已安装依赖启动文件是否存在；启动文件缺失但目录仍在时，安装器会继续下载并解压整个包，直到最后因正式目录存在而失败。
- 用户不能用重新安装修复缺少启动文件的游戏，还会额外付出下载和解压耗时。
- 修复方向：任务开始前区分未安装、已安装、部分损坏三种情况。对于已登记游戏的修复，应在明确确认及互斥下提交；对于身份不明的现存目录，应提前拒绝，不能先下载，也不能盲目删除。

### 6. [P2] 解压大文件期间取消和进度都要等待当前文件结束

- 位置：`src-tauri/src/services/game_body_package_service.rs:712`、`:733`、`:756`。
- 取消检查位于文件循环开头，逐块读取和写入的内部循环没有检查；进度也只在每个文件结束后更新。
- 对含数 GB 单个资源包的游戏，点击取消后仍会持续写入整个文件，进度可能长时间不变化。外层最终会检查取消，因此这主要是长时间不能响应取消，而非一定错误报告成功。
- 修复方向：在现有块循环检查取消，按已写字节并节流更新进度，保持失败清理暂存目录的行为。

## 行为缺口与次要事项

1. **不同云端版本覆盖安装尚未接通。** `src/components/GameStorePage.vue:340` 对所有已安装游戏禁用下载；后端 `baidu_commands.rs:1577` 也直接拒绝。因此目前仅支持本地未安装时下载，并未实现先前约定的“选择其他版本，确认后替换本地唯一版本”。这是需要补齐的行为，不应直接删除目录存在检查来实现。
2. **轮询异常可能让商店一直显示安装中。** `src/App.vue:657` 使用定时器再次调用异步轮询，后续 `getTask` 失败没有被首次入口的 try/catch 捕获，也没有安排下一次轮询。应在轮询内部处理错误并恢复可重试状态。
3. **传输中心重试安装成功没有专门的立即刷新。** `TransferCenter.vue:75` 直接发起新安装任务；`App.vue:371` 仅对 session 任务结束触发库刷新。当前库有 30 秒缓存与周期刷新兜底，因此属于可能延迟显示，不是记录必然未保存。
4. **下载进度换算存在饱和。** `baidu_commands.rs:1611` 在 u8 上先做 `saturating_mul(3)`，下载后段显示会提前封顶，再跳到解压阶段。应先扩展数值范围再换算。
5. **下载、解压未见磁盘空间预检。** 打包已有预检，安装链路尚未按 ZIP 与解压体积检查目标空间。正式下载前可利用已有远端大小与可信清单估算，失败仍需正常清理，不能仅依赖预检。

## 已确认的保护

- 下载先写唯一临时文件，确认下载字节数并同步后才重命名；正常错误退出由守卫清理下载临时文件。
- 解包检查相对路径、清单文件集合、启动程序、逐文件大小和总大小；有预期哈希时会验证整包 SHA-256。
- 正常解压失败和取消会清理暂存目录；启动时会清理上次遗留的云端安装暂存目录。
- 从商店直接发起且轮询正常的成功安装会强制刷新游戏库和商店，不会自动启动游戏。
- 当前实现拒绝覆盖已存在的正式目录，因此不能把上述恢复缺口描述成已经发生了覆盖原游戏的数据丢失。

## 修复结果

上述六个缺陷及行为缺口已在本轮代码中修复。

| 项目 | 修复后的行为 |
| --- | --- |
| gameKey 关联 | 新安装采用校验后的远端 gameKey；按键匹配已有记录时保留本地 UID 和名称，拒绝重复键及 UID 冲突。 |
| 安装提交与恢复 | 下载、解压、封面读取均在目录提交前完成；先写持久化安装事务，再切换目录并提交游戏记录。普通失败回滚，中断后启动恢复。 |
| 本地与远端 UID | 云端 ZIP 通过选定清单的 SHA-256、版本、大小及文件数绑定来源，不再错误要求源 UID 等于本地 UID；操作锁采用解析后的本地 UID，并额外防止同 gameKey 并发安装。 |
| 清单与整包校验 | 清单读取错误、缺失、路径或 fsId 不符、包大小不符及无有效 SHA-256 均明确失败，不能静默降级跳过校验。下载时计算的 SHA-256 直接复用。 |
| 损坏目录重装 | 已登记游戏经用户确认后可重新安装或选择其他云端版本覆盖；身份不明的现存目录在下载前拒绝。 |
| 大文件解压 | 每 1 MB 读写块检查取消，按解压字节更新进度；提前检查清单总大小及 ZIP 条目大小，失败清理本次暂存文件。 |
| 覆盖安装 | 商店及传输中心重试都要求确认；保留当前已配置的游戏内受保护存档，外部存档目录不改动，完成后不自动启动。 |
| 临时旧本体 | 仅为提交失败回滚临时移动旧目录，成功后立即删除；清理被占用时保留事务和游戏操作锁，提示重启继续清理，不形成可选择的长期本体历史版本。 |
| 下载 ZIP | 每次安装使用独立缓存路径；失败仅清理本次下载，提交后才清理被同版本新缓存替代且不再被引用的旧 ZIP。 |
| 轮询与刷新 | 轮询读取失败解除前端等待并引导到传输中心；传输中心重试安装成功也刷新游戏库及商店。 |
| 进度与空间 | 先扩大整数范围再换算下载百分比；下载前预检 ZIP 与解压所需空间，解压前再次预检。 |

实现集中于新增的 `src-tauri/src/services/game_body_install_service.rs`，负责安装身份、清单选择、存档保留、提交与恢复。命令层负责任务和服务编排；已有 ZIP 服务继续负责包校验与解压，入口只注册模块并调用启动恢复。
