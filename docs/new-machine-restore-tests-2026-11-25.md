# 新机下载与存档还原测试

日期：2026-11-25。项目：GameSaverNext，当前版本 1.0.39。

## 目标与隔离方式

没有第二台电脑时，用独立目录和独立子进程验证跨设备的数据恢复链路。

测试先生成旧机的云端档案、本体 ZIP 和存档 ZIP，然后删除旧机目录及其对象库，只留下模拟云端文件。新机子进程从空的本地记录开始，使用不同的用户目录、游戏库目录与本地游戏 UID。`USERPROFILE`、`APPDATA`、`LOCALAPPDATA` 和 `PROGRAMDATA` 仅在子进程中覆盖，父进程环境不变。

所有文件读写均位于随机测试工作目录。恢复前会断言目标范围属于该目录。测试不读取真实百度凭证，不连接真实网盘，不修改用户游戏库、实际存档和平台配置。

云端传输使用本地 ZIP 夹具替代；档案构造与合并、本体压缩与解压、安装提交、存档包编码与对象导入、恢复计划、当前存档保护校验、物理恢复和事务恢复均调用正式实现。仓库测试入口仅替代 Tauri AppHandle 提供的目录和历史查询；不会开启既有测试夹具的“不验证当前备份”选项。

## 覆盖的流程节点

1. 导出游戏记录、启动参数、存档保护配置和版本数据。
2. 在空记录中合并云端档案：保留 gameKey，生成新本地 UID，重复恢复不产生重复游戏或保护配置。
3. 未安装时启动前检查拒绝启动。
4. 下载夹具本体包，计算整包 SHA-256，调用正式解压入口，核对文件数与大小。
5. 提交本体安装并重新读取持久化记录，验证启动条件及启动参数。
6. 验证本体包没有夹带受保护存档，必须单独还原存档。
7. 验证存档 ZIP 整包哈希、游戏身份、版本身份及对象哈希，并导入全新的对象库。
8. 恢复到新机路径，逐个比较实际存档字节，更新当前版本并验证同步状态。
9. 重复恢复同一版本，验证内容不变且没有重复登记版本。

串联测试覆盖游戏目录、LocalLow、Roaming AppData、Local AppData、Saved Games 和 ProgramData。不同范围故意使用同名 `slot.dat`，但内容不同，验证不会串档。

Documents 的 Known Folder 重定向、公共文档路径及自定义路径重新绑定仍由项目中已有的专项测试覆盖；本次串联夹具不向真实 Documents 目录写入。

## 新增回归场景

| 场景 | 验证内容 |
| --- | --- |
| 空白新机正常恢复 | 旧机文件已删除，六类范围均还原为正确字节，重复恢复结果一致 |
| 安装记录提交失败 | 安装目录回滚，不生成已安装记录，游戏仍无法启动 |
| 存档对象缺失 | 安全失败，六个范围中的原存档全部保留 |
| 存档对象损坏 | SHA-256 校验失败，六个范围中的原存档全部保留 |
| 取消对象导入 | 不进入物理恢复，原存档保持不变 |
| 恢复后撤销 | 正式回滚入口恢复所有范围的原始内容 |
| 未提交的恢复中断 | 丢弃内存恢复凭据，重新读取记录并执行启动恢复，撤销未提交内容 |
| 已提交的恢复中断 | 重新读取带提交标记的记录，启动恢复保留新内容并清理事务 |
| 缺少本体或自定义目录 | 拒绝隐式创建，不越过本体安装和自定义路径确认要求 |

中断场景模拟的是进程停止后遗留的磁盘状态，再调用正式启动恢复入口，不是电源断电实验。

## 本次实际发现并修复

新机尚未运行游戏时，受保护存档目录通常不存在，且本体包已排除这些目录。原恢复白名单未包含 ManagedGame 和 ProgramData，导致正常的新机恢复在计划阶段失败。

恢复白名单现允许创建这两类范围。ManagedGame 仍先检查本体存在、目标位于受管游戏内；Custom 仍拒绝隐式创建。链接、目标冲突、对象完整性和当前存档保护检查均保留。

首次串联运行结果为 5 通过、1 失败，失败原因是受管游戏内的 SaveData 不存在。修复后通过，再补充中断恢复与根目录检查。

## 执行方法

在项目根目录执行：

```powershell
cargo test --manifest-path .\src-tauri\Cargo.toml --lib new_machine_
```

结果：新增 9 个测试通过。另有 1 个标记为 ignored 的子进程工作入口，由父测试自动调用，不需要手动运行。

全量回归：

```powershell
cargo test --manifest-path .\src-tauri\Cargo.toml --lib
cargo check --manifest-path .\src-tauri\Cargo.toml
```

全量 Rust 测试结果：588 通过、0 失败、3 忽略。忽略项包含上述子进程工作入口。

`cargo check` 与 `git diff --check` 均通过。编译只报告已有的未使用代码警告。

## 验证边界

这些测试验证数据和文件系统恢复链路，不等同于实际新机验收。浏览器授权、真实网盘网络响应、前端按钮到命令的整条交互、Windows 新账号的 Known Folder/权限差异，以及真实游戏能否读取恢复后的进度，未由本夹具覆盖。

后续需要端到端验证时，可以在同一台电脑的 Windows Sandbox、虚拟机或单独 Windows 用户中完成，无需准备另一台实体电脑。涉及真实网盘时，使用专用测试游戏和独立 gameKey。

本次未修改版本号、未构建新安装包。该修复在重新打包后才会进入安装版。
